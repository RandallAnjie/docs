# Rdocs 完整权限系统

## 目标

Rdocs 的权限系统遵循五条不可绕过的原则：

1. 所有文档空间都必须先通过设备密钥登录；不存在匿名访客会话。
2. 所有权限判断都在 Worker 服务端执行，前端隐藏按钮只用于改善体验。
3. 默认拒绝访问；授权主体必须属于资源所在的同一组织。
4. 权限变更立即递增 ACL 版本并关闭旧协作连接，旧票据不能继续编辑。
5. 页面分享链接与组织成员体系隔离，分享链接永远只读。

## 身份与租户边界

- 一个用户可以加入多个组织，每个组织都是独立租户。
- 空间、页面、用户组、附件、评论、版本、分享链接和审计记录都绑定 `organization_id`。
- 跨组织用户、用户组或资源 ID 不能用于授权；接口统一拒绝租户不匹配。
- 用户被停用或移出组织后，空间与页面访问立即失效。
- `usr_phase0_system` 只保留为内部历史记录引用，不再是任何组织成员，也不能登录或访问租户内容。

## 组织角色

| 组织角色         | 组织设置             | 成员和用户组                 | 创建空间 | 受限空间默认访问 | 说明                                           |
| ---------------- | -------------------- | ---------------------------- | -------- | ---------------- | ---------------------------------------------- |
| 所有者           | 管理、删除、转让     | 管理                         | 可以     | 管理员           | 每个组织唯一，拥有最终恢复能力                 |
| 管理员           | 管理，不可删除或转让 | 管理；只有所有者可管理管理员 | 可以     | 无权限           | 不会因为组织管理员身份自动看到私密内容         |
| 成员             | 不可管理             | 不可管理                     | 可以     | 无权限           | 组织可见空间默认只读                           |
| 外部只读（历史） | 不可管理             | 不可查看、不可加入用户组     | 不可以   | 无权限           | 不再允许新建；必须被单独授权，且永远封顶为只读 |

新邀请只能选择“管理员”或“成员”。历史 `guest` 记录只用于兼容已有数据，可以被升级为正式成员或移出组织，不能再次创建。

## 资源权限

空间和受限页面使用同一套面向用户的四档权限：

| 权限   | 查看/下载/导出 | 评论 | 编辑/自动保存 | 新建/移动/删除/恢复 | 管理权限 |
| ------ | -------------- | ---- | ------------- | ------------------- | -------- |
| 无权限 | 否             | 否   | 否            | 否                  | 否       |
| 只读   | 是             | 否   | 否            | 否                  | 否       |
| 读写   | 是             | 是   | 是            | 是                  | 否       |
| 管理员 | 是             | 是   | 是            | 是                  | 是       |

数据库中的 `commenter` 是历史兼容角色：可以查看和评论，但不能编辑。新管理界面不再创建该角色；已有记录仍能正确执行和显示，管理员可将其改为四档中的任意一档。

空间“管理员”可以管理空间设置、空间授权和空间内页面。页面“管理员”只管理该页面权限边界及其内容，不会因此获得空间设置权限。

## 空间授权计算

空间可以是：

- `organization`：正式组织成员默认只读。
- `restricted`：没有显式授权就不能进入。

除组织所有者外，空间权限按以下顺序计算，遇到更高优先级后不再使用低优先级：

1. 用户直接授权。
2. 用户组授权；多个组取最高权限，但任意同级用户组的“无权限”优先拒绝。
3. 整个组织授权。
4. 空间可见性的默认权限。

“无权限”是显式拒绝，优先级与其授权主体一致。删除一条授权表示恢复继承，不等于无权限。

历史外部只读成员不继承整个组织的默认权限或组织授权，不能加入用户组，只能获得用户直接授权。无论数据库中存在何种旧授权，最终有效权限都会被服务端封顶为只读。

## 页面授权计算

页面默认为 `inherit`，继承空间或最近的受限祖先页面权限。页面切换为 `restricted` 后，它成为自己及后代的权限边界。

访问某个页面时：

1. 先确认用户拥有该空间的基础访问权。
2. 从当前页面向上寻找最近的 `restricted` 页面。
3. 如果没有受限边界，使用空间权限。
4. 如果有受限边界，按“用户 > 用户组 > 整个组织”解析该边界的授权。
5. 页面授权可以把空间只读用户提升为该页面的读写或页面管理员，也可以显式拒绝。
6. 空间管理员绕过页面限制；页面管理员不能反向管理空间。

历史外部只读成员在页面层同样永久封顶为只读。

## 匿名分享

- 未登录用户不能访问组织、空间、页面树、搜索、评论、协作写入或附件 API。
- 只有持有有效分享令牌的用户能打开对应分享页面。
- 分享票据固定为 `viewer`，不能编辑、评论或管理权限。
- 分享链接可随时撤销或设置过期时间；撤销后附件读取也立即失效。
- 分享身份在协作者列表中显示为“外部只读”，不会伪装成组织成员。

## 权限变更与实时协作

影响空间、用户组、成员状态或页面权限边界的操作都会更新受影响页面的 `acl_version`，清理短期权限缓存，并通知 Durable Object 关闭现有连接。客户端重新连接时必须获取新票据，因此：

- 被降权或显式拒绝的用户不能继续使用旧 WebSocket 编辑。
- 外部只读成员即使拿到历史编辑票据，也会在 ACL 更新后被关闭。
- 自动保存不需要用户点击保存，但每次同步仍受票据角色与当前 ACL 版本约束。

## 管理界面

- 组织成员邀请不再显示访客角色。
- 历史外部只读成员会明确标注，管理员只能将其升级为正式成员、停用或移除。
- 用户组选择器不显示历史外部只读成员。
- 空间和页面权限选择器统一显示“无权限 / 只读 / 读写 / 管理员”。
- 对历史外部只读成员只显示“无权限 / 只读”。
- 权限界面明确区分“无权限”和“移除授权（恢复继承）”。

## 必须持续通过的安全回归

1. 未登录请求不能读取任何业务 API。
2. `AUTH_MODE=phase0` 等旧配置不能重新开启匿名模式。
3. 跨租户主体不能被加入空间或页面授权。
4. 用户直接“无权限”能覆盖用户组、组织授权和组织可见默认值。
5. 用户组“无权限”能覆盖同级的其他用户组授权。
6. 历史外部只读成员的空间、页面和协作票据均不能超过只读。
7. 历史外部只读成员不能加入用户组，不能通过邀请重新创建。
8. 组织管理员不能自动进入未授权的受限空间。
9. 页面管理员不能修改空间设置。
10. 权限变更后旧协作连接会被关闭，旧 ACL 票据被拒绝。
