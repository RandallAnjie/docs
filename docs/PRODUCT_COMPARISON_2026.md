# Rdocs 与 Notion、飞书文档、飞书多维表格对照

更新时间：2026-08-14 UTC

对照范围：Rdocs v0.1 当前实现，以及厂商在 2026-08-14 可访问的官方帮助文档。竞品能力会继续变化，本文以链接中的官方说明为准。

## 定位结论

Rdocs 当前应继续定位为“可自托管、设备密钥优先、权限边界清晰的多人协作知识库”。它与 Notion、飞书文档直接竞争的是页面、知识空间和协作文档闭环；飞书多维表格属于结构化业务数据、视图和自动化平台，不应该被硬塞进 Rdocs 的页面 CRDT 或页面 ACL 模型。

Rdocs v0.1 已经覆盖团队文档的主链路：多组织、成员与邀请、用户组、空间、页面树、实时协作、无感自动保存、协作者光标气泡、评论与提及、版本、搜索、私有附件、回收站、分享链接和离线缓存。它还不是 Notion 或飞书的全产品替代品。

## Rdocs 已形成的差异化

1. **设备密钥优先**：不引入 GitHub OAuth 或密码数据库；服务端只保存设备公钥和哈希后的应用会话。
2. **恢复不会污染当前正文**：历史版本恢复创建新的 document generation，旧票据、旧连接和旧 IndexedDB 世代不能重新合并回来。
3. **页面权限只收窄、不放大**：页面限制边界最终角色不会高于空间角色，降低复杂继承规则导致越权的概率。
4. **私有附件贯穿所有入口**：内部读取检查页面权限；公开分享也必须持有仍有效且对应同一页面的 share token。
5. **可控部署**：应用、元数据、正文协调和对象存储都运行在 RandallFlare 上，Rdocs 不修改平台实现。

## 与成熟产品的真实差距

- Notion 和飞书文档拥有更广的内容块、嵌入、原生客户端、移动端、企业治理和第三方生态。
- Rdocs 的离线能力是浏览器 IndexedDB 缓存与重连合并，不等于原生客户端的完整离线产品体验。
- Rdocs 当前公开分享只读；匿名评论、审核流、发布站点、自定义域名、SSO/SCIM 尚未进入 v0.1。
- Rdocs 的 Markdown 导入导出是单页级；空间 ZIP、组织级归档、PDF/HTML 高保真导出尚未实现。
- 浏览器到 R2 的直传需要 RandallFlare 为 Rdocs 提供项目级 S3 凭据或等价的短期签名接口；当前使用经过 Worker 鉴权的 25 MB 流式上传，因此功能可用，但没有达到“大附件不经过 Worker”的成本路径。
- 飞书多维表格的行列权限、公式、关联记录、多视图、自动化、仪表盘、应用模式和 AI 是另一套结构化数据平台。Rdocs 当前没有这些能力，也不应以文档表格节点冒充。

## 后续产品顺序

1. 先完成真实设备密钥启用和多账号生产验收，关闭 `phase0`。
2. 为现有文档能力补齐多浏览器 E2E、安全回归、备份对账和容量压测。
3. 增加空间/组织级批量导出、邀请邮件投递、设备密钥管理和企业审计保留策略。
4. 如果用户确实需要“多维表格”，新建独立的 Structured Data 模块：独立表/字段/记录模型、行列权限、视图查询和自动化；页面只通过稳定引用嵌入它，不复用 Yjs 正文作为数据库真相。
