# Rdocs v0.1 实施状态

更新时间：2026-08-14 UTC

需求基线：`/root/TeaKKi-Cloudflare-Design-v0.1.md`

## 总体结论

Phase 0 高风险协作闭环、Phase 1 MVP 产品闭环和 Phase 2 日常可用性均已在代码中实现。生产环境仍有两项需要外部条件完成：用户本人登记首把真实设备密钥后关闭 `phase0`，以及发布后运行完整多账号线上验收。

设计文档把 Notion 式数据库、白板、项目管理、AI、SSO/SCIM、原生客户端等列为 v0.1 非目标或 Phase 3 扩展，因此不把这些项目伪报为当前完成项。竞品边界见 [2026 产品对照](PRODUCT_COMPARISON_2026.md)。

## 上线前剩余动作

1. 先应用 D1 migrations `0004`–`0007`，再发布本分支代码。
2. 运行格式、类型、单元/集成测试、构建和原生 WebSocket/恢复 smoke。
3. 用户本人按 [设备密钥手册](PASSKEY_SETUP.md) 登记至少一把真实密钥并验证登录后，将 `AUTH_MODE` 从 `phase0` 切到 `passkey`。
4. 使用两个真实账号验证邀请、空间/页面授权、评论、撤权、分享和附件；生产数据在第 3 步前仍不应视为私密。

## 已知非阻塞差异

- RandallFlare 已修复此前的平台阻塞；历史见 [平台修复清单](RANDALLFLARE_PLATFORM_ISSUES.md)。
- `rrangler d1 migrations apply` 的账本参数写入存在 RF-7；本次已在备份后精确应用并重建 Rdocs 账本，schema 与外键检查通过。
- Rdocs 当前没有 browser→R2 直传所需的项目级短期签名配置，因此附件走鉴权 Worker，单文件限制 25 MB。功能、权限和数据保留闭环不受影响，大附件成本路径尚未达到设计推荐值。
- 本机随附的 `workerd 2026-08-14` 当前只接受到 `2026-07-08` 的 compatibility date，导致本地完整 Worker 浏览器验收无法启动；生产 RandallFlare 不受该本地工具版本限制。
