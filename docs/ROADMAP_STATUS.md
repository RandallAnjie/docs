# Rdocs 实施进度与顺序

更新时间：2026-08-14 UTC

需求基线：`/root/TeaKKi-Cloudflare-Design-v0.1.md`，以其中第 25 节“实施路线”和第 26 节“MVP 验收标准”为准。若界面占位与该文档冲突，以需求基线为准。

## 总体结论

- Phase 0：8 项中 7 项已完成；仅“按平台休眠逐出条件验证对象重新初始化”仍受 RandallFlare 验收能力限制。
- Phase 1：13 项中 2 项完整、5 项部分完成、6 项尚未开始。
- Phase 2：尚未正式开始；界面中的评论、收藏和最近访问目前只是占位，不计为完成。
- Rdocs 已用 HTTP/Yjs 兼容通道完成正文、presence 和光标闭环；RandallFlare 已反馈原生 WebSocket 修复，仍须在正式域名重新跑原生链路验收。

按用户可用的完整 MVP 衡量，目前约完成四成。按高风险协作基础设施衡量，完成度更高。

## 后续固定实施顺序

1. 登录和应用会话。
2. 组织、成员和邀请。
3. 空间创建、切换和设置。
4. 补齐页面移动、排序、删除和回收站。
5. 冻结并补齐 MVP 编辑器 Schema。
6. 用正式身份实现统一空间权限函数和角色矩阵。
7. 完成自动版本策略与版本预览。
8. 标题和正文搜索。
9. 图片和附件。
10. 基础活动与审计。
11. 进入 Phase 2：评论、通知、收藏、最近访问等日常可用性。

任何 RandallFlare 缺失能力单独记录到 `docs/RANDALLFLARE_PLATFORM_ISSUES.md`，不通过修改平台仓库或降低 Rdocs 数据正确性要求来规避。
